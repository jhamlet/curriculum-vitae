# Pattern: Outcome Framing

## When to Apply

- Bullet points describe activities without impact
- Responsibilities listed without results
- Vague "worked on" or "helped with" language
- Missing quantifiable achievements

## Approach

Transform activity descriptions into business outcomes using the
pattern:

> **Built X** -> **Delivered Y resulting in Z**

1. Start with the deliverable, not the activity
2. Include the business context or stakeholder benefit
3. Add quantifiable impact when available
4. Connect technical work to organizational goals

### Impact Categories

| Category   | Examples                                   |
| ---------- | ------------------------------------------ |
| Efficiency | Reduced time by X%, saved Y hours/week     |
| Scale      | Handled Xk users, processed Y records/day  |
| Quality    | Reduced bugs by X%, improved uptime to Y%  |
| Revenue    | Increased conversion by X%, saved $Y       |
| Adoption   | X teams adopted, Y% developer satisfaction |
| Speed      | Reduced deploy time from X to Y            |

## Example Transformations

**Activity-focused:**

> Built a React component library for the design system.

**Outcome-framed:**

> Delivered shared component library adopted by 5 product teams,
> reducing feature development time by 30% and ensuring design
> consistency across applications.

---

**Vague:**

> Worked on improving the CI/CD pipeline.

**Outcome-framed:**

> Reduced deployment cycle from 45 minutes to 8 minutes by optimizing
> CI/CD pipeline, enabling 3x more daily deploys and faster incident
> response.

---

**Responsibility-based:**

> Responsible for maintaining the API layer.

**Outcome-framed:**

> Maintained API layer serving 50k daily requests at 99.9% uptime, while
> reducing p95 latency from 800ms to 120ms through targeted
> optimizations.

---

**Task-based:**

> Wrote unit tests for the payment module.

**Outcome-framed:**

> Achieved 95% test coverage on payment module, catching 3 critical bugs
> before production and reducing payment-related incidents by 60%.

## Trade-offs

| Gain                               | Cost                                     |
| ---------------------------------- | ---------------------------------------- |
| Demonstrates business value        | Requires knowing/estimating impact       |
| More compelling to hiring managers | May need to verify numbers in interviews |
| Shows strategic thinking           | Can feel boastful if overdone            |
| Differentiates from other resumes  | Not all work has measurable outcomes     |
